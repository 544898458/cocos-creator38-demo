# 法线贴图修复指南

> 本项目大量使用 AI 生成的贴图，其中"法线贴图"多数是 AI 画的**法线风格图**（看起来像法线贴图的照片），不是数学上有效的法线数据，会导致光照错乱。本文记录检验方法、修复流程和 Blender 5.1 的坑。

## 一、如何判断法线贴图是否有效

切线空间法线贴图的基准色是 `(0.5, 0.5, 1.0)` = 浅紫色（表示"法线朝上"），凹凸信息藏在 R/G 通道相对 0.5 的微小偏差里。**贴图本身看起来"平"是正常的**，不要用肉眼判断。

用数值检验（Python 脚本 `backups/scan_normal_maps.py`）：

| 指标 | 有效值 | AI 风格图的典型值 |
|---|---|---|
| R 均值 | ≈ 0.500 | 0.2~0.4 |
| G 均值 | ≈ 0.500 | 0.2~0.4 |
| B 均值 | ≈ 0.95+ | 0.6~0.8 |
| **单位化比例**（\|n\|²≈1 的像素占比） | **≈ 100%** | 7%~70% |

**单位化比例 > 80% 才算有效**，这是最可靠的单一指标。

同理，PBR 参数贴图（metallic/roughness 打包图）也有规范：苔藓/有机物 metallic 应处处为 0，roughness 应 0.85+。metallic 有随机噪声会渲染出金属斑点。

## 二、修复流程（按颜色贴图高度场生成）

原理：颜色图的亮度近似代表表面起伏（亮的凸、暗的凹），由高度场的 Sobel 梯度可解析计算切线空间法线：

```
n = normalize( -gx*S, -gy*S, 1 )   (gx, gy 为亮度的像素域梯度, S 为强度系数)
```

强度系数 S 由**模型几何**标定（这是与"随便加个滤镜"的本质区别）：

```
world_per_uv = sqrt( Σ模型世界面积 / Σ模型UV面积 )   ← Blender 导入 FBX 计算
height_amp   = 1% × 模型世界对角线                    ← 高度幅度
S = height_amp × SIZE / world_per_uv
```

这样法线凹凸强度与模型实际尺寸、UV 密度匹配，且与颜色图**像素级对齐**（高度直接源自颜色图）。

**主脚本：`backups/blender_fix_all_normals.py`**，输入清单 JSON（法线文件 / 配对颜色图 / 所属 FBX），批量输出 1024 PNG。清单由 `backups/build_fix_manifest.py` 从预制体扫描生成。

### 处理过的三种颜色源情况

1. 材质引用了独立的颜色贴图文件 → 直接用
2. 颜色贴图内嵌在 FBX 里（mainTexture 指向 FBX 自身 uuid）→ Blender 导入 FBX 后从 `bpy.data.images` 取（排除名字带 normal/法线 的）
3. FBX 无内嵌贴图 → 借用同 FBX 其他材质的颜色图

## 三、Blender 5.1 的坑（重要）

1. **`ROUGHNESS` 烘焙类型已移除**：`sc.render.bake.type = 'ROUGHNESS'` 会抛异常。roughness 是亮度的线性映射，直接用 numpy 生成即可（等效且更精确）。
2. **`selected-to-active` 法线烘焙失效**（5.1.1 实测）：即使"平面目标+抬角源"的教科书案例也输出均匀平面值，场景设置和 op 参数两种方式都不行。**不要走射线烘焙路径，直接用解析法**（上面的 Sobel 方案数学上等价）。
3. **Displace 修改器的位移在局部空间**：FBX 导入常带 cm→m 缩放（物体 scale 0.01），按世界尺寸算的强度会小 100 倍，全部射线落空、输出均匀 (0.5,0.5,1)。要按**局部空间**尺寸计算，或干脆不用修改器，用 bmesh 直接写顶点。
4. Blender 内置 Python **没有 PIL**，图片读写用 `bpy.data.images`（注意 `pixels` 行 0 是底部），numpy 数值计算可用（Blender 自带 numpy）。

## 四、部署方式

1. **覆盖原文件**（保 uuid，材质引用不变，编辑器自动重新导入）：JPEG 用 quality=95 + subsampling=0 保存，PNG 直接存。原文件先备份到 `backups/备份_原法线贴图/`
2. **CDN 上传**：1024 版本统一放在 `backups/上传CDN_法线贴图1024/`；苔蔓的另有 `backups/上传CDN_苔蔓法线贴图1024.png` / `上传CDN_苔蔓四通道PBR贴图2048.png`
3. 游戏运行时 CDN 高清图会覆盖本地贴图的，CDN 不修就白修（苔蔓踩过的坑）

## 五、命名规格与强度调节

**命名规格**：法线贴图文件名里的数字 = 该文件的实际分辨率（`xx法线贴图128.jpeg` 就是 128×128）。修复数据以 1024 为母版，另存一份名字数字为 1024 的兄弟文件；原 128/64/32/256 文件从 1024 母版 LANCZOS 缩小覆盖。材质默认引用小图，需要高清时在编辑器里换成 1024 版本或上传 CDN。

**强度调节**：生成的法线按"高度幅度 = 模型尺寸 1%"标定。游戏里觉得凹凸不明显/太夸张，调材质的 `normalStrength` 参数即可，不用重烘焙。

## 六、颜色贴图去 AI 颗粒 + 宏观凹凸

- **去噪**：Blender 5.1 的合成器 Denoise 节点在后台模式输出损坏（结果缓冲不落盘），Cycles OIDN 会把纹理颗粒当"细节"保留（仅降 18%）。改用 numpy 双边滤波（`backups/denoise_bilateral.py`，9x9 窗口保边）：颗粒降 ~50%，结构相关性 0.9999
- **重要教训**：按颜色高度生成法线时，**高度场必须先低通**，否则坡度会被单 texel 细碎梯度主导——宏观结构零坡度，法线在游戏里缩小采样后"看起来是平的"。低通半径是"颗粒粗细"的调节旋钮（苔蔓最终用 r=1 + unsharp 锐化 1.2x，见下）

## 七、烘焙法线的符号陷阱 + 解析法重生成（苔蔓案例）

Blender 烘焙出来的苔蔓法线经坡度场对照检验发现：**空间位置对齐，但 R/G 两通道符号相对 OpenGL 标准约定都是反的**（相当于"亮=凹"，光照方向镜像）——烘焙管线是黑盒，无法修正。解析法重生成（`backups/gen_moss_normal_analytic.py`）：

- **符号约定（PIL 读图，行 0 = 图像顶部）**：`R = -dH/dx`，`G = +dH/dy_down`（v 向上），`B = 1/sqrt(1+sx²+sy²)`
- **验证方法**：法线坡度场 vs 高度场解析坡度做互相关，翻转对照应 ≈0、直接对照应显著为正（苔蔓达 0.96/0.97）；也可从法线 FFT 积分重建高度场对照原图
- **缩小法线贴图必须重归一化**：LANCZOS 缩小后相邻法线平均导致向量变短（单位化掉到 88%、坡度变缓），逐像素 `v/|v|` 恢复到 100%
- 苔蔓的高度源 = **去噪图**（r=1）+ unsharp 锐化（细节 ×2.2）；"颗粒粗细"调 `GaussianBlur` 半径（r 越大越柔和宏观，越小越细，<1 即残余噪声）

## 八、苔蔓贴图集规格（2026-11 最终版）

`assets/Scene资源/` 下三套图 × 三档分辨率（2048/1024/128，命名后缀 = 实际分辨率）：

| 类型 | 源 | 说明 |
|---|---|---|
| 颜色 | `苔蔓高强降噪*.png` | 双边滤波去噪版（CDN 名为 `苔蔓2048.png`） |
| 法线 | `苔蔓法线贴图*.png` | 解析法，高度源 = 去噪图低通+锐化 |
| PBR | `苔蔓四通道PBR贴图*.png` | R=metallic 0，G=roughness `0.92-0.07*lum`（0.85~0.92），B/A 预留 |

运行时：`苔蔓Component` 加载 CDN `图片/苔蔓2048.png`、`苔蔓法线贴图2048.png`、`苔蔓四通道PBR贴图2048.png` 直用 2048；本地 128 套（`苔蔓.mtl`）是低配/测试初始值。**重打包脚本**：`backups/regen_moss_pbr.py`（PBR 三件套）、`gen_moss_normal_analytic.py`（法线三件套+CDN件）。
