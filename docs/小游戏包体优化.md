# 微信小游戏包体优化

> 微信小游戏主包/分包合计上限 30 MB。本项目构建目录 `build/wechatgame-wechatgame`，优化前 30.9 MB 超限。本文记录体积分布结论与已验证的手段（2026-11）。

## 一、体积分布结论（30.9 MB 时）

图片侧油水很少：197 张图片合计仅 4.1 MB。**大头是模型和序列化数据**：

| 类别 | 代表文件 | 体积 |
|---|---|---|
| FBX 模型 | `地图27处理法向.fbx`（Terrain 内嵌几何） | 2.9 MB |
| 引擎 JS | `_virtual_cc.js` | 1.9 MB |
| 序列化 JSON | import/*.json（prefab/场景） | ~3 MB（多个 0.5~1 MB） |
| 物理 wasm | `bullet.release.wasm` | 0.45 MB |
| 字体 | `OpenSans-Bold.ttf` | 0.21 MB |
| 图片 | 全部 197 张 | 4.1 MB |

## 二、已执行：法线 PNG → JPEG（-1.3 MB）

`Hatchery_法线贴图Morph_1024.png`（1.57 MB）→ JPEG q92（0.30 MB）。

**关键操作**：格式转换时**保 uuid**——重写 meta 的 `files` 列表为 `.jpeg` 但 uuid 不变，材质引用零改动。脚本 `.codebuddy/skills/wechat-package-optimize/scripts/morph_normal_to_jpeg.py`。法线转 JPEG 是标准做法（q92 + subsampling=0，坡度数据损失可忽略）。

## 三、后续备选手段（按性价比排序）

| 目标 | 可省 | 做法 |
|---|---|---|
| `地图27处理法向.fbx` | ~2 MB | 改 glb 压缩或远程加载（地形模型最大单项） |
| `bullet.wasm` | 0.45 MB | 项目未用 3D 物理时，项目设置去掉 physics 模块 |
| `p_Base_02.fbx` 内嵌资源 | ~0.3 MB | 同 FBX 压缩路线 |
| 地堡/炮台 256 PBR 贴图 | ~0.2 MB | PNG→JPEG（同样保 uuid 手法） |
| `OpenSans-Bold.ttf` | ~0.15 MB | 字体子集化 |

## 四、排查方法

1. 全量扫描：`python` 遍历 build 目录按大小排序（`.codebuddy/skills/wechat-package-optimize/scripts/identify_build_files.py`）
2. 识别来源：build 内文件名是 uuid（`xxxx.png` / `xxxx@hash.bin`），拿 uuid 反查 `assets/**/.meta` 得到源资产路径
3. **换格式/换尺寸的万能手法**：只改文件内容和 meta 的 `files` 字段，uuid 不动，所有引用（FBX 内嵌材质的 `userData.materials`、prefab、mtl）都无需改动
4. 改完必须重新构建才能反映到包体
